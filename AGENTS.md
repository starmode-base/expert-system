# Agent guidelines

## Linting

This project uses `strictTypeChecked` TypeScript ESLint rules. Lint incrementally as you write code — don't defer all linting to the end. Never disable linting rules (e.g. `eslint-disable`). Fix the underlying typing issues instead.

Always run checks when done coding:

```bash
npx tsc --noEmit && bun run lint && bun run format
```

## TanStack Router route generation

The route tree (`src/routeTree.gen.ts`) is auto-generated by the TanStack Router Vite plugin at build time (`vinxi build`). However, the CI/CD pipeline runs `tsc` **before** `vinxi build`, so TypeScript will fail if the route tree is stale.

**When you create a new route file under `src/routes/`, you must manually update `src/routeTree.gen.ts`** to register the route. Follow the existing patterns in that file — for a new top-level route `/foo/$fooId` you need to:

1. Add an import: `import { Route as FooFooIdImport } from './routes/foo.$fooId'`
2. Create the route: `const FooFooIdRoute = FooFooIdImport.update({ id: '/foo/$fooId', path: '/foo/$fooId', getParentRoute: () => rootRoute } as any)`
3. Add entries to `FileRoutesByPath`, `FileRoutesByFullPath`, `FileRoutesByTo`, `FileRoutesById`
4. Add the path/id to all union literal types inside `FileRouteTypes` (`fullPaths`, `to`, `id`)
5. Add the route to `RootRouteChildren` interface and `rootRouteChildren` object
6. Add the route to the `ROUTE_MANIFEST_START` JSON block (root `children` array + its own entry)

Do **not** try to regenerate the tree via CLI commands — use the manual update pattern above.

### Linking to routes with `validateSearch`

If a route defines `validateSearch`, TanStack Router requires a `search` prop on any `<Link>` pointing to it. Pass explicit values for all search keys (they can be `undefined` if optional):

```tsx
<Link to="/some-feed" search={{ query: undefined, filters: undefined }} />
```

## Database schema changes

During development, apply schema changes using `bun run db:push` (`drizzle-kit push`) instead of generating migrations. Do **not** run `drizzle-kit generate` or `drizzle-kit migrate` while iterating on schema changes. Migrations should only be generated once, right before submitting the PR.
